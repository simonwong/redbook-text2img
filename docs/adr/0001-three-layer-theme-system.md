# 使用三层主题系统

图片样式采用三层结构：样式基础保存不可编辑的视觉与导出规则；样式配置保存用户可编辑的语义选择；主题是有名称的完整样式配置。这样既能让 8 个内置主题一键生效，又能让用户在同一组配置上继续修改，而无需理解 CSS。

## Decision

建立一个深 `Style System` Module。它通过单一 Seam 提供主题目录、持久化数据恢复、状态转换、有效配置读取和渲染样式解析。设置界面、主题缩略图、预览和导出不得自行合并主题默认值、派生颜色或生成 CSS。

主题定义只包含元数据和完整样式配置。所有当前主题能力，包括受控背景、内容容器、密度、字体、标题、封面版式和备忘录画布，都应由样式配置中的封闭选项表达。若以后出现无法合理开放的主题细节，必须增加有名称的封闭变体；禁止加入任意 CSS 覆盖袋。

正文标题与封面使用独立语义字段。正文标题对齐和大小只在正文解析时生效；封面版式只决定封面内容位置。装饰颜色只参与标题装饰派生，不得覆盖 Markdown 高亮、链接、列表或引用颜色。高亮装饰必须根据标题文字色保持至少 4.5:1 对比度。

运行状态保存内置主题标识和稀疏用户覆盖。切换或重置主题会清除样式覆盖并采用当前主题配置；卡片标记保持不变。渲染样式和主题默认值不持久化。未来自定义配置通过增加新的配置来源复用相同 Style System，本期不实现创建、命名、保存和管理。

设置界面固定显示主题、背景、排版、正文标题、封面、卡片标记六组，不使用折叠。每个被覆盖的样式字段都显示文字状态并支持单项恢复主题值。密度只提供紧凑、均衡、舒展三档；字体只提供跟随主题、无衬线、衬线三种可靠且有区分度的选择。旧五档密度和已移除字体在恢复时确定性迁移。

界面按内容所需宽度分为三种展示：小于 768px 使用底部抽屉；768–1199px 保留编辑器与预览双栏，设置使用右侧覆盖层；至少 1200px 才把设置作为第三栏嵌入。三种展示复用同一配置内容和语义。

Style System 保持纯 in-process，不依赖 React 或 Zustand。状态容器只负责订阅和存储；所有业务规则留在 Module 内。主测试 Seam 是 Style System Interface，覆盖 8 个主题、封面与正文、配置转换、旧数据迁移、对比度以及 `html2canvas-pro` 安全约束。

## Considered Options

- 保留“主题完整 CSS + 用户调整”的双数据模型：拒绝。调用方必须理解合并顺序，主题无法主要由用户可见配置表达。
- 让 Style System 直接提供 React hooks 和控件文案：拒绝。Interface 更短，但领域规则会绑定展示框架。
- 建立动态字段和插件注册表：拒绝。本期只有一个本地实现和固定配置集合，动态 Seam 只有假设价值。

## Consequences

- 新增配置字段时，需要同时定义合法值、默认值、迁移、解析和设置界面，但调用方无需理解其内部规则。
- 内置主题改进会自动传播到用户没有覆盖的字段；用户显式修改继续保留。
- 背景必须使用受控方案或经校验的纯色，不能持久化任意 CSS、远程资源或无限渐变。
- 画布背景作为单一语义字段保存：内置方案使用封闭标识，纯色只接受 6 位十六进制值。样式基础根据背景明暗自动选择可读语义色。
- 内容底板使用无底板、浮层卡、备忘录三值封闭集合；底板和画布背景分别覆盖、分别恢复，但由同一解析流程生成预览与导出样式。
- 密度从旧五档迁移为三档：`compact`/`snug` → `compact`，`normal` → `balanced`，`relaxed`/`spacious` → `spacious`。
- 旧字体确定性迁移：`system`/`rounded`/`mono` → `sans`，`kai` → `serif`；非法字体仍被丢弃。
- 旧的 `FullStyle`、调整合并和 CSS 生成类型退到 Module 实现内部，不再作为跨 Module Interface。
